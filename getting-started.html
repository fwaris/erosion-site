    Getting started¶

    Create a standalone app¶

    From the directory where you keep your projects, install the generator and create a repository for your app.

    cargo install --git https://github.com/fwaris/erosion.git --rev 62683cae8cdf60c89a539e9389fa449eef63f271 --locked cargo-erosion
cargo erosion new hello-mobile --id com.example.hellomobile --name "Hello Mobile"
cd hello-mobile
cargo test --locked

    With an Android device connected, run ./scripts/run-android.ps1 in PowerShell on Windows. With an iPhone simulator booted, run bash scripts/run-ios.sh on your Mac. Tap Increment and the count changes from 0 to 1.

    Open src/lib.rs to change the counter. Add a variant to Msg, handle it in update, and bind a control to it in view. The generated AGENTS.md describes this pattern for contributors and coding agents. Share the repository with its lockfile. Teammates can use its local scripts directly. Screens and state

    Platform setup¶

    Android requires PowerShell 7, JDK 21, Android SDK Platform 35, Build Tools 36.0.0, NDK r27d, and the Rust targets aarch64-linux-android and x86_64-linux-android. On an Apple Silicon Mac install Xcode, an iOS simulator runtime, XcodeGen, and the Rust targets aarch64-apple-ios and aarch64-apple-ios-sim. Use rustup target add from the repository root.

    Run one sample¶

    To explore the three framework examples, clone the Erosion repository and run these commands from its root. Each command builds, installs, and opens the selected application.

    Sample Android on Windows (PowerShell 7) iOS on a Mac (Bash)
    Controls Gallery ./scripts/run-android.ps1 gallery bash scripts/run-ios.sh gallery
    Falling Blocks ./scripts/run-android.ps1 falling-blocks bash scripts/run-ios.sh falling-blocks
    Field Catch ./scripts/run-android.ps1 field-catch bash scripts/run-ios.sh field-catch

    Android. Start an emulator or connect a phone with USB or wireless debugging enabled. With multiple devices connected, use adb devices -l and append -Serial <serial>.

    iOS. Start an iPhone simulator, or pass its UDID to boot it, for example bash scripts/run-ios.sh gallery "$SIMULATOR_UDID". List simulators with xcrun simctl list devices available. For a paired physical iPhone, set DEVELOPMENT_TEAM to your Apple team ID and run bash scripts/run-ios.sh gallery --device "$IPHONE_UDID" with the phone unlocked. Find the device with xcrun devicectl list devices.

    Field Catch multiplayer. Start cargo run --locked -p field-catch-broker in a separate terminal. Android forwards port 8787 automatically in local mode. An iOS simulator can use the broker on its Mac. For a physical iPhone or players on separate computers, follow the Field Catch network setup in the repository’s sample guide.

    Upgrade a generated app¶

    1. In the app's Cargo.toml, set both Erosion Git dependencies to the same new commit. Run cargo update -p erosion-ui -p erosion-native-host and commit Cargo.lock. Preserve the Rust package name, Android application ID, iOS bundle ID, and app data keys so the installed app upgrades in place.
    2. Replace study.mobile.StudyActivity with dev.erosion.host.ErosionActivity in the Android manifest and in the component launched by scripts/run-android.ps1. Keep the existing rust.app metadata. For custom JNI callers, the bridge class is dev.erosion.host.ErosionBridge and its shared library is liberosion.so.
    3. In the XcodeGen project, change ios/Study.swift to ios/ErosionApp.swift and native-host/StudyBridge.h to native-host/ErosionBridge.h under the same framework checkout. Keep the existing RustApp value and scene declaration. Custom C callers now use erosion_exchange and erosion_release.
    4. Change Rust imports and matches from erosion_ui::Event to erosion_ui::HostEvent. Existing Application implementations and native factories continue to work. A single-screen counter can replace its adapter and export with erosion_ui::erosion_app!(Model::default, update, view); and remove the old adapter imports. Apps with lifecycle hooks can implement erosion_ui::app::DeclarativeApp and return an AppAdapter from their factory.
    5. Run cargo test --locked, then run the app's Android and iOS scripts. Install over the existing app and check a previously saved setting on both platforms.
